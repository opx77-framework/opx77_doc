title: Events
description: The public opx:on:* server events any resource can listen to, the private opx:in:* events, and the client side.
---

On the server, `TriggerEvent` reaches **every** running resource. `opx_infinity` announces what happens on `opx:on:<module>:<verb>` names raised through [`OPX.Publish`](/docs/opx_infinity/core/server#opx-publish). Any server resource can listen; no allowlist applies.

```lua title="my_logs/server/main.lua"
AddEventHandler('opx:on:character:money', function(playerId, payload)
	print(('%s %s %d %s (now %s)'):format(payload.citizenId, payload.action,
		payload.amount, payload.moneyType, tostring(payload.balance)))
end)
```

Every event has two arguments:
- playerId: `number?` — the player the event is about; `nil` when that character is not online
- payload: `table` — built for the event; never a live record, never the free-form `metadata`

The events are announcements: they fire after the change, and nothing a listener does can undo or veto it.

<Callout type="warn" title="Advisory, not proof">

Server `TriggerEvent` is host-wide in both directions: **any** server resource can raise an `opx:on:*` name with any payload. Use these events to refresh, log or react — never as proof that something happened. Before you pay, give or unlock on the strength of one, ask OPX again (a read export such as [`GetMoney`](/docs/creators/server/getmoney), [`CountItem`](/docs/creators/server/countitem) or [`GetVehicle`](/docs/creators/server/getvehicle)). For a server-started bar, keep the `id` [`StartProgress`](/docs/creators/server/startprogress) answered and check `owner` too.

</Callout>

## opx:on:character:loaded [#opx-on-character-loaded]

Server, host-wide. A character was loaded for a player.

```lua
AddEventHandler('opx:on:character:loaded', function(playerId, payload) end)
```

- payload: `table` — the public view
  - `source`, `citizenId`, `userId`, `firstName`, `lastName`, `money`, `job`, `gang`, `jobs`, `gangs`

## opx:on:character:unloaded [#opx-on-character-unloaded]

Server, host-wide. A character left the world (logout, switch, disconnect).

```lua
AddEventHandler('opx:on:character:unloaded', function(playerId, payload) end)
```

- payload: `{ citizenId, userId }`

## opx:on:character:created [#opx-on-character-created]

Server, host-wide. A character row was made (no name and no body yet: those come in the world).

```lua
AddEventHandler('opx:on:character:created', function(playerId, payload) end)
```

- payload: `{ citizenId, userId, slot }`

## opx:on:character:deleted [#opx-on-character-deleted]

Server, host-wide. A character was deleted (soft: the row stays, the slot is freed). Forget whatever you keep for this citizen id.

```lua
AddEventHandler('opx:on:character:deleted', function(playerId, payload) end)
```

- playerId?: `number` — set when the character was being played
- payload: `{ citizenId, userId, by }` — `by` is the connection that asked (the player, staff), `nil` for the console

## opx:on:character:money [#opx-on-character-money]

Server, host-wide. Any balance change.

```lua
AddEventHandler('opx:on:character:money', function(playerId, payload) end)
```

- payload: `table`
  - citizenId: `string`
  - moneyType: `string`
  - amount: `integer`
  - action: `'add' | 'remove' | 'set'`
  - reason?: `string`
  - balance: `integer?`
  - offline: `boolean` — `true` (and `playerId` nil) for [`AddMoneyOffline`](/docs/creators/server/addmoneyoffline#export-server-addmoneyoffline)

## opx:on:character:job [#opx-on-character-job]

Server, host-wide. The primary job was set, its duty changed, or a job membership was removed.

```lua
AddEventHandler('opx:on:character:job', function(playerId, payload) end)
```

- payload: `table`
  - citizenId: `string`
  - job: `table` — the primary job after the change
  - removed?: `string` — the job removed
  - offline: `boolean` — the change was made to a character nobody is playing

## opx:on:character:gang [#opx-on-character-gang]

Server, host-wide. The same for gangs.

```lua
AddEventHandler('opx:on:character:gang', function(playerId, payload) end)
```

- payload: `{ citizenId, gang, removed?, offline }`

## opx:on:inventory:changed [#opx-on-inventory-changed]

Server, host-wide. A container's contents were written.

```lua
AddEventHandler('opx:on:inventory:changed', function(playerId, payload) end)
```

- payload: `table`
  - `kind`, `owner`, `container`
  - citizenId?: `string` — only for a player's bag (and then `playerId` is set)

## opx:on:inventory:used [#opx-on-inventory-used]

Server, host-wide. A player used an item (already consumed; nothing can decide the use from here).

```lua
AddEventHandler('opx:on:inventory:used', function(playerId, payload) end)
```

- payload: `{ citizenId, name, slot, consumed, metadata }`

## opx:on:inventory:items [#opx-on-inventory-items]

Server, host-wide. What a player's bag gained and lost, **by item name**: a give, a pickup, a drop, a craft, a use, an export call. A drag inside the bag moves nothing in or out and raises nothing.

```lua
AddEventHandler('opx:on:inventory:items', function(playerId, payload)
  for _, change in ipairs(payload.changes) do
    if change.name == 'lockpick' and change.delta > 0 then print('got a lockpick') end
  end
end)
```

- payload: `table`
  - citizenId: `string`
  - changes: `{ name, delta, count }[]` — `delta` the units that moved (negative for a loss), `count` what the bag holds now; sorted by name

<a id="downed" />

## opx:on:downed:changed [#opx-on-downed-changed]

Server, host-wide. A player went down or got up.

```lua
AddEventHandler('opx:on:downed:changed', function(playerId, payload) end)
```

- payload when down: `{ citizenId, down = true, waiting, restored }`
  - restored: `boolean` — the down state came back after a reconnect
- payload when up: `{ citizenId, down = false, reason, kept }`
  - kept: `boolean` — the character left the world still down; the state returns with them

## opx:on:vehicles:spawned [#opx-on-vehicles-spawned]

Server, host-wide. An owned vehicle was brought out.

```lua
AddEventHandler('opx:on:vehicles:spawned', function(playerId, payload) end)
```

- payload: `table`
  - `citizenId`, `plate`, `record`, `vehicleId`
  - vehicleKey: `string` — the engine id as text (safe in JSON)
  - recalled?: `true` — it was already out and was moved

## opx:on:vehicles:stored [#opx-on-vehicles-stored]

Server, host-wide. It was put away, or the host removed it from the world.

```lua
AddEventHandler('opx:on:vehicles:stored', function(playerId, payload) end)
```

- payload: `{ citizenId, plate, garage }`, or `{ citizenId, plate, removed }` — `removed` says why the host took it away

## opx:on:vehicles:registered [#opx-on-vehicles-registered]

Server, host-wide. A vehicle row was made for a character: bought at a dealer, given by [`AddVehicle`](/docs/creators/server/addvehicle) or a staff command.

```lua
AddEventHandler('opx:on:vehicles:registered', function(playerId, payload) end)
```

- payload: `{ citizenId, plate, record, garage }`

## opx:on:vehicles:state [#opx-on-vehicles-state]

Server, host-wide. A vehicle was moved to stored or **impounded** ([`SetVehicleState`](/docs/creators/server/setvehiclestate), the impound door).

```lua
AddEventHandler('opx:on:vehicles:state', function(playerId, payload) end)
```

- payload: `{ citizenId, plate, state, garage }` — `state` is `'stored'` or `'impounded'`

## opx:on:dealership:sold [#opx-on-dealership-sold]

Server, host-wide. A vehicle was bought at a dealer (`counter`) or sold player-to-player (`offer`).

```lua
AddEventHandler('opx:on:dealership:sold', function(playerId, payload) end)
```

- payload (counter): `{ kind = 'counter', citizenId, plate, entry, record, dealer, garage, price, currency }`
- payload (offer): `{ kind = 'offer', citizenId, plate, entry, record, dealer, garage, price, currency, seller, sellerCitizenId, company, commission, banked, pending }`
  - `citizenId` is the buyer; `seller` / `sellerCitizenId` the salesperson.
  - garage?: `string` — the buyer's chosen garage; `nil` = the vehicles module default
  - company: `string` — `<kind>:<group>`
  - commission: `integer` — paid to the seller (`0` if it could not be paid; it then went to the company)
  - banked: `integer` — the company's share
  - pending: `boolean` — `true` when the company share went to the pending ledger to be paid in later; the sale is done either way

## opx:on:hauling:sold [#opx-on-hauling-sold]

Server, host-wide. Crates were sold to a drop-off NPC.

```lua
AddEventHandler('opx:on:hauling:sold', function(playerId, payload) end)
```

- payload: `{ citizenId, site, dropoff, count, pay, each, currency }`

## opx:on:doorlock:changed [#opx-on-doorlock-changed]

Server, host-wide. A door was locked or unlocked — by a player, staff, autolock or an export.

```lua
AddEventHandler('opx:on:doorlock:changed', function(playerId, payload) end)
```

- playerId: `number?` — `nil` when no player turned it (autolock, an export)
- payload: `table`
  - id, door: `integer` — the door id (the same value twice)
  - name: `string`
  - state: `0 | 1` — `1` locked
  - locked: `boolean`
  - by: `string` — the player id, `lockpick:<id>`, `staff:<id>`, `autolock` or the contract caller
  - item?: `string` — the key item that opened it, if any

See [doorlock](/docs/opx_infinity/doorlock).

<a id="progress" />

## opx:on:progress:finished [#opx-on-progress-finished]

Server, host-wide. A bar the server started ended, **as the server decided it**: [`StartProgress`](/docs/creators/server/startprogress).

```lua
AddEventHandler('opx:on:progress:finished', function(playerId, payload) end)
```

- payload: `table`
  - id: `integer` — the id `StartProgress` answered
  - owner: `string` — the resource (or module) that started it; filter on your own name
  - ending: `string` — `finished`, `stopped`, `cancelled`, `interrupted`, `refused` (the client could not draw it), `rejected` (finished sooner than its duration), `no_answer`, `left`
  - completed: `boolean` — **only `true` means the action happened**
  - elapsedMs: `integer` — by the server's clock

## The private opx:in:* events [#private]

<Callout type="warn" title="Server opx:in:* events are visible to every server resource">

Because server `TriggerEvent` is host-wide, the internal `opx:in:*` events (for example `opx:in:character:loaded`) also reach your resource, and your resource could raise them. They are **not** part of the public surface: their names and arguments change without notice. Listen to the `opx:on:*` events above instead, and never raise an `opx:` event yourself.

</Callout>

## On the client [#client]

The client-side `opx:on:*` events (menu actions, inventory opened…) stay inside `opx_infinity`: a client `TriggerEvent` does not leave its resource. Answers to your own client calls reach you through the [reply export](/docs/creators/client#replies), and some client events can be forwarded with [`Subscribe`](/docs/creators/client#subscribe).
