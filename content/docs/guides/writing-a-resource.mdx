For a resource that is **not** part of `opx_infinity` (your own `my_jobs`, for example). It uses the curated surface `opx_infinity` publishes for creators. If you need a module's full contract (every function of `character`, `inventory`…), write a [module](/docs/guides/writing-a-module) instead.

## What a separate resource can use [#surface]

| Surface | Side | Use it for | Read |
|---|---|---|---|
| Server exports | server | read a player's data, money, job, items, down state, the roster, the jobs, the catalogue, vehicles, doors; change money, jobs, gangs, duty, your own metadata (online or not), items, stashes, chat, keys, vehicles, doors; register items, use handlers and crafting benches; a toast; a bar the server judges; revive | [Server exports](/docs/creators/server) |
| Client exports | client | open a menu, form or panel, show a toast, run a progress bar, put rows on the eye and hints on the key strip, open your crafting bench, play an animation, read the local player; subscribe to OPX client events | [Client exports](/docs/creators/client) |
| Public server events | server | react when a character loads, money moves, an item is used, a car is bought… | [Server events](/docs/creators/events) |
| [Player state bag](#state-bag) | client and server, read | name, job, gang, citizen id of any player in the same bucket, with no call at all | below |
| [opx_lib](#opx-lib) | client | input, markers, zones, RPC helpers… | [opx_lib](/docs/opx_lib) |
| [Ordinary commands](#commands) | server | running an unrestricted command | below |

Start with [For creators](/docs/creators): the answer every export gives, the allowlist the operator controls (writes are refused until your resource is in `SERVER.EXPORTS.WRITERS`), and when you must `await`.

## A minimal example [#example]

```lua title="my_jobs/open77.lua"
resource "my_jobs"
version "1.0.0"
dependency "opx_infinity"
server_script "server.lua"
client_script "client.lua"
permissions { "network.events" }
```

```lua title="my_jobs/client.lua"
exports('OnOpxEvent', function(event, payload) TriggerEvent(event, payload) end)

RegisterCommand('jobmenu', function()
	exports.opx_infinity:OpenMenu({
		title = 'ODD JOBS',
		closeOnSelect = true,
		items = { { id = 'deliver', label = 'Deliver a parcel' } },
	})
end)

AddEventHandler('opx:on:menu:action', function(p)
	if p.action == 'select' and p.itemId == 'deliver' then
		TriggerServerEvent('my_jobs:start')
	end
end)
```

<Tab value="Server">

```lua title="my_jobs/server.lua"
-- the operator adds my_jobs = true to SERVER.EXPORTS.WRITERS
RegisterNetEvent('my_jobs:start', function()
	local playerId = source
	CreateThread(function()
		local job = exports.opx_infinity:GetJob(playerId)        -- a read: sync is fine
		if not job.ok then return end
		-- ... run the job, check it on the server, then pay:
		local pending = Open77.exports.call('opx_infinity', 'AddMoney',
			playerId, 'EDDIES', 200, 'odd job')
		local answer = pending and pending:await()
		if answer and answer.ok then
			exports.opx_infinity:SendChat(playerId, { text = 'Paid 200 €$', kind = 'info' })
		end
	end)
end)

AddEventHandler('opx:on:character:unloaded', function(playerId, payload)
	-- forget anything you kept for payload.citizenId
end)
```

`SendChat` is a write too, so it needs the same allowlist entry; it answers at once, so the sync form works.

## The player state bag [#state-bag]

The [character module](/docs/opx_infinity/character/client#state-bag) writes public facts about each loaded character on the player's replicated state bag. Any resource reads them with no permission and no call.

```lua
local who = Open77.state.player(playerId)
if who.job and who.job.name == 'police' then
	-- ...
end
```

- Keys: `citizenId`, `name`, `charInfo`, `job`, `gang`, `username`, `life`.
- A client only receives bags of players in **its own routing bucket**.
- Money, metadata and inventory are not in the bag; use the server exports.

## opx_lib [#opx-lib]

A client library any resource may use.

```lua title="my_resource/open77.lua"
dependency "opx_lib"
```

```lua
local Lib = require('@opx_lib')
print(Lib.Manifest())   -- the permissions line your manifest needs
```

## Commands [#commands]

A server resource whose manifest declares `runtime.commands` can queue an **unrestricted** command line with `ExecuteCommand(line)`. Restricted (staff) commands are refused, and the answer goes to the server log.

## Things to avoid [#avoid]

| Do not | Why |
|---|---|
| Listen to or raise `opx:in:*` events | Server `TriggerEvent` is host-wide, so you can see them, but they are private and change without notice. Use the [public events](/docs/creators/events). |
| Write to `opx_infinity`'s tables directly | It bypasses its rules, hooks and audit, and its in-memory copy overwrites your change. Read-only access is possible with `database.access`. |
| Trust a client | The client exports act on one player's screen. Charge, give and check on the server. |

## What you still cannot do [#cannot]

| You want to | Status |
|---|---|
| Veto an action (hooks) | `OPX.Hooks` runs inside `opx_infinity` only: a veto answers inside the action, synchronously, and a call into another resource cannot be bounded there. |
| Hear any OPX client event | Only the events on the [Subscribe list](/docs/creators/client#subscribe). |
| Open an impound or garage screen for a player, or gate a garage on a job | No export yet. |
| Run an item shop of the `shops` module | `shops` is the clothing shop. Sell with your own menu and [`RemoveMoney`](/docs/creators/server/removemoney) + [`AddItem`](/docs/creators/server/additem), or a [crafting bench](/docs/creators/server/registercraftingbench). |
| Register a weapon at runtime | [`RegisterItem`](/docs/creators/server/registeritem) refuses weapons and ammunition: they need a TweakDB record and a class from `data/weapons.lua`. |

What used to be on this list and is not any more: the panel, the key strip and the eye ([client exports](/docs/creators/client#exports)), a bar the server starts and judges ([`StartProgress`](/docs/creators/server/startprogress)), an offline character's metadata ([`SetMetadata`](/docs/creators/server/setmetadata) with a citizen id), runtime items and use handlers ([`RegisterItem`](/docs/creators/server/registeritem), [`RegisterUsableItem`](/docs/creators/server/registerusableitem)).

A request/answer between your client and your server is [`Lib.Callback`](/docs/opx_lib) in `opx_lib`, over `Open77.net`: it is between your own two halves and needs no export.

Code written for the old `opx77_*` exports does not work as is; see [From opx77_* to opx_infinity](/docs/migration/from-opx77).
