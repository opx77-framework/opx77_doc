---
title: From opx77_* to opx_infinity
description: Where every old opx77_* resource, export, event, command and config key went when the framework became the single opx_infinity resource, and what has no replacement.
---


In September 2026 the separate `opx77_*` resources were replaced by **one resource, `opx_infinity`**; each old resource is now a **module** inside it. General changes first, then one folded table set per old resource.

## What changed for everyone [#general]

| Before | Now |
|---|---|
| Sixteen documented `opx77_*` resources (twenty-one in all) | One resource, `opx_infinity`, plus the client library `opx_lib` |
| Each resource published exports (`Open77.exports.call('opx77_core', ...)`) | Modules call each other's [contracts](/docs/opx_infinity/concepts/modules-and-contracts#contracts) with `OPX.Api.Get('<module>')`, inside `opx_infinity` only. |
| Answers `{ ok = true, ... }` with fields at the top level | Contracts mostly answer `Result`: `{ ok = true, value = ... }` / `{ ok = false, error, detail }`. Money mutators still answer `ok, code`. Each module page gives the exact shape. |
| A service found its caller with `GetInvokingResource()` | The caller passes its own `owner` name (menus, prompts, effects, animations). |
| Events `opx77:client:*`, `opx77:server:*`, `<resource>:*` | [`opx:net:<module>:<verb>`, `opx:on:...`, `opx:in:...`](/docs/opx_infinity/concepts/events) |
| Client events heard by other resources | Client `opx:on:` events stay inside `opx_infinity`. |
| Commands `opx77.*`, rights `command.opx77.*` | Commands `opx.*`, rights `command.opx.*`; optional [short aliases](/docs/opx_infinity/core/config#config-server-command-aliases). |
| One config global per resource (`OPX_HUD_CONFIG`) | `config/<module>.lua` setting `OPX.Config.MODULES.<module>`. `LOCALE` keys are gone from module configs; the language is [`SHARED.LOCALE`](/docs/opx_infinity/core/config#config-shared-locale). |
| One CEF page per resource | One [WebUI page](/docs/opx_infinity/concepts/webui) for every screen. |
| `OPX.*` helpers in lowerCamel (`OPX.Result.ok`) | PascalCase (`OPX.Result.Ok`). See the [API reference](/docs/opx_infinity/core). |
| Database tables `opx77_*` | **Same names**, kept. Several modules still read old tables and adopt their rows at boot. No migrations run. |

## For a separate resource that used the old exports [#separate]

No drop-in replacement, but a curated set: call `opx_infinity` instead of `opx77_core`, with new names and the operator's allowlist in front. See [For creators](/docs/creators).

| Old call | New call |
|---|---|
| `opx77_core` client `GetPlayerData`, `HasJob`, `HasGang` | server exports `GetPlayerData`, `HasJob`, `HasGang`; the client export [`GetPlayerData`](/docs/creators/client/getplayerdata) for the local player (the state bag is empty since PR #93) |
| `opx77_core` server `GetIdentity` | server exports `GetPlayerData`, `GetPlayerByCitizenId` |
| `opx77_core` server `GetVersion` | server export `GetVersion` |
| `opx77_inventory` `AddItem`, `RemoveItem`, `HasItem`, `GetItemCount` | server exports `AddItem`, `RemoveItem`, `HasItem`, `CountItem` |
| `opx77_menu` `open`, `update`, `close` | client exports `OpenMenu`, `UpdateMenu`, `CloseMenu` (answers through your `OnOpxEvent` export) |
| `opx77_input` `open`, `close` | client exports `OpenForm`, `CloseForm` |
| `opx77_notify` `show`, `dismiss` | client exports `ShowToast`, `DismissToast` |
| `opx77_animations` `play`, `stop` | client exports `PlayAnimation`, `StopAnimation` |
| `opx77_chat` server `chat:addMessage` | server exports `SendChat`, `BroadcastChat` |
| server events `opx77:player:loaded`, `moneyChange`, `jobUpdate`… | public server events `opx:on:character:loaded`, `money`, `job`… |
| `opx77_core` `OPX.SetJob`, `SetGang`, `RemovePlayerFromJob`, `SetJobDuty` (in-VM) | server exports `SetJob`, `SetGang`, `RemoveJob`, `RemoveGang`, `SetDuty` |
| `opx77_core` `OPX.SetMetadata`/`GetMetadata` | server exports `SetMetadata`/`GetMetadata`, in your resource's own `ext.<resource>.*` space |
| client events `opx77:client:onMoneyChange`, `onJobUpdate`, `opx77:status:needs`… | client export `Subscribe('opx:on:character:money')` and the other [subscribable events](/docs/creators/client#subscribe) |

- Anything not in that set must move into a [module](/docs/guides/writing-a-module).
- In the folded tables below, "no exports" describes the first `opx_infinity` release; the creator exports above were added afterwards.

<Accordion title="opx77_core (character part), opx77_charselector, opx77_charcreator">

Modules: `character` replaces the character half of `opx77_core` (roster, money, groups, metadata, placement, commands, hooks, data/ files). `entry` replaces `opx77_charcreator` (the name form; face via appearance). `opx77_charselector` is removed: there is no selection screen, the account is locked on one character and commands move the lock. `spawn`, `theme`, `diagnostics` are new (no old resource); `/opx77` status maps to `diagnostics`.

Key change for every old caller: the old exports are gone; opx_infinity publishes only the curated [creator exports](/docs/creators). Everything below is a contract function (`OPX.Api.Get('character')`) reachable only from code inside opx_infinity. From another resource, use the [creator exports](/docs/creators) and the public server events. The player state bag carries nothing since PR #93.

<Accordion title="opx77_core (runtime part) and opx77_notify">

Covers `opx77_notify` (all of it) and the parts of `opx77_core` that became core or lib functions
(hooks, notifications/refusals, cooldowns, lifecycle/gate, buckets, storage, logging, tunables,
locale, utility). Character/money/jobs/vehicles/inventory parts of `opx77_core` belong to the
character, vehicles and inventory module pages.

General rule: `opx_infinity` publishes NO Open77 exports. Everything below is callable only by code
running inside `opx_infinity`. Function names moved from lowerCamel to PascalCase.
