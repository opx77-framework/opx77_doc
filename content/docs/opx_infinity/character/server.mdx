title: Server
description: The character contract on the server — players, money, metadata, jobs and gangs, characters and accounts.
---

```lua
local character = OPX.Api.Get('character')
```

From server code inside opx_infinity.

- An **identifier** is a [`Player`](/docs/opx_infinity/character/player#player) table, a player id (`number`) or a citizen id (`string`). Only a citizen id reaches an offline character.
- *Yields*: reads or writes the database; run it in a coroutine (`CreateThread`).
- `Result` is `{ ok = true, value = ... }` or `{ ok = false, error = code, detail = ... }`.
- **Money**: types come from `MONEY.TYPES` in `config/shared.lua` (`EDDIES`, `BANK` shipped). The mutators work on **loaded characters only**, answer `ok, code` (`code` a locale key) and do not yield; the autosave writes the change. Every successful change sends [`opx:net:character:money`](/docs/opx_infinity/character/events#opx-net-character-money) to the owner, raises the internal money event and writes an audit line.
- **Jobs and gangs**: a character holds any number of each, one grade per membership; one of each is **primary** (`PlayerData.job`, `PlayerData.gang`). Functions that write membership rows yield even for a loaded character. With an offline character's citizen id, the change is written to the row.
- **Self-service** character functions take the caller's `source` and act on that account only. Somebody else's character answers `character.notFound` (same as a missing one) and the attempt is audited.
- **Staff** functions do no permission check: call them only after your own ACL check (the `admin` module does).

## GetPlayer [#server-character-getplayer]

The loaded character on a player id.

```lua
character.GetPlayer(source)
```

**Parameters**
- source: `number`

**Returns**
- `Player?` — nil for a connection with no character

```lua title="Example"
local player = character.GetPlayer(source)
if player then print(player.PlayerData.citizenId) end
```

## PlaceCharacter [#server-character-placecharacter]

Kill-then-respawn placement. Yields.

```lua
character.PlaceCharacter(player, target)
```

**Parameters**
- player: `Player`
- target?: `{ x, y, z, heading?, bucket? }`
  - Omitted: the stored position, then `DEFAULT_SPAWN`.

**Returns**
- `boolean`, `string?` — `ok, reason`

```lua title="Example"
CreateThread(function()
  local ok, why = character.PlaceCharacter(player, { x = 0.0, y = 0.0, z = 50.0, heading = 90.0 })
  if not ok then print(why) end
end)
```

## AddMoney [#server-character-addmoney]

Runs hook [`money:beforeAdd`](/docs/opx_infinity/character/events#hooks).

```lua
character.AddMoney(identifier, moneyType, amount, reason)
```

**Parameters**
- identifier: `Player | number | string`
- moneyType: `string`
- amount: `number` — rounded; must be positive and finite
- reason?: `string`

**Returns**
- `boolean`, `string` — `ok, code`

```lua title="Example"
local ok, code = character.AddMoney(source, 'BANK', 250, 'delivery')
if not ok then print(code) end
```

## RemoveMoney [#server-character-removemoney]

Refuses (`money.insufficient`) rather than going below zero, unless the type is in `MONEY.ALLOW_NEGATIVE`. Runs `money:beforeRemove`. The hook may yield: afterwards the player must still be loaded and the balance is checked again, so one balance cannot pay twice.

```lua
character.RemoveMoney(identifier, moneyType, amount, reason)
```

**Parameters**
- identifier: `Player | number | string`
- moneyType: `string`
- amount: `number`
- reason?: `string`

**Returns**
- `boolean`, `string` — `ok, code`

## AddMoneyOffline [#server-character-addmoneyoffline]

Adds money whether or not the character is being played. **Yields.**

- Online: same as `AddMoney` (`offline = false`).
- Offline: runs hook `money:beforeAddOffline`, writes the row directly, audits `money.addOffline` and publishes `opx:on:character:money` with `offline = true`.

```lua
character.AddMoneyOffline(citizenId, moneyType, amount, reason)
```

**Parameters**
- citizenId: `string`
- moneyType: `string`
- amount: `number`
- reason?: `string`

**Returns**
- `Result` — `{ balance, offline }`; errors `character.notFound`, `money.badType`, `money.badAmount`, `money.vetoed`, `error.unavailable` (row being written, or boot failed)

## FindCharacters [#server-character-findcharacters]

**Staff.** Searches every account. 25 per page. Yields.

```lua
character.FindCharacters(query)
```

**Parameters**
- query: `table`
  - `mode`: `'recent'` (last played first) or `'search'`
  - `term?`: `string` — 3–48 bytes, against name, account name, citizen id
  - `seenAt?`, `cursor?` — from the previous page

**Returns**
- `Result` — `{ characters, mode, more, cursor, seenAt }`

```lua title="Example"
local page = character.FindCharacters({ mode = 'search', term = 'vik' })
```

## RemoveCharacter [#server-character-removecharacter]

**Staff.** Soft-deletes any character. Ignores `SELF_DELETE`. Yields.

```lua

```

**Parameters**
- citizenId: `string`
- source?: `number`

**Returns**
- `Result`

<Callout type="error" title="Deleting a character">

A delete stamps `deleted_at` and keeps the row, but every module that owns per-character data (clothes, needs, containers, vehicles…) **really deletes** its rows, and so does every `CASCADE_TABLES` entry. There is no undo. A character being played is disconnected.

</Callout>
