---
title: Shared library (lib/)
description: Every helper in opx_infinity's lib/ directory — results, text, numbers, validation, hooks, locales, citizen ids, job gates, placed spots, storage, audit logging and the WebUI surface.
---

`lib/` holds the plain helpers every module uses. They load before any module, on the side shown, and like the rest of `OPX` are only reachable from code inside `opx_infinity`. A separate resource can use the client-side [`opx_lib`](/docs/opx_lib) instead — a different library. Runtime functions (`OPX.Modules`, `OPX.Scheduler`, `OPX.Refuse` …) are under [Core](/docs/opx_infinity/core).

# Result [#result]

`lib/shared/result.lua`, both sides. A Result is `{ ok = true, value = v }` or `{ ok = false, error = code, detail = text? }`: `error` is a stable code to branch on, `detail` is for the log only ([Result convention](/docs/opx_infinity/core/error-codes#result)).

## OPX.Result.Ok [#opx-result-ok]

```lua
OPX.Result.Ok(value)
```

**Parameters**
- value?: `any` — may be `nil`

**Returns**
- `{ ok = true, value }`

## OPX.Result.Err [#opx-result-err]

```lua
OPX.Result.Err(code, detail)
```

**Parameters**
- code: `string`
- detail?: `string`

**Returns**
- `{ ok = false, error, detail }`

```lua title="Example"
if not row then return OPX.Result.Err('not_found') end
return OPX.Result.Ok(row)
```

# Validate [#validate]

`lib/shared/validate.lua`, both sides. For values that came from a client. Both answer a [Result](#result).

## OPX.Validate.Text [#opx-validate-text]

Trims text and checks its length in characters and its pattern. Input longer than `max × 4 + 16` bytes (at most 1024) is refused before any work.

```lua
OPX.Validate.Text(value, opts)
```

**Parameters**
- value: `any`
- opts?: `table`
  - min?: `integer` — default 1
  - max?: `integer` — default 255
  - pattern?: `string`

**Returns**
- `Result` — value is the trimmed text; errors `type`, `too-long`, `not-utf8`, `too-short`, `format`

```lua title="Example"
local name = OPX.Validate.Text(payload.name, { min = 2, max = 32 })
if not name.ok then return OPX.Refuse(source, 'error.badRequest', 'thing.rename') end
```

# Hooks [#hooks]

`lib/shared/hooks.lua`, both sides. Named points where code inside `opx_infinity` can veto an action.

## OPX.Hooks.Register [#opx-hooks-register]

Lower priority runs first; equal priorities keep registration order. Raises if `name` is not a string or `fn` not a function.

```lua
OPX.Hooks.Register(name, fn, priority)
```

**Parameters**
- name: `string`
- fn: `function(payload)` — return exactly `false` to veto
- priority?: `number`

**Returns**
- `integer` — id

```lua title="Example"
OPX.Hooks.Register('money:beforeAdd', function(p)
	if p.amount > 1000000 then return false end
end)
```

## OPX.Hooks.Remove [#opx-hooks-remove]

Also stops a trigger already in progress from calling it.

```lua
OPX.Hooks.Remove(id)
```

**Parameters**
- id: `integer`

**Returns**
- `boolean` — removed

## OPX.Hooks.Trigger [#opx-hooks-trigger]

Runs every hook in order. Stops and answers `false` at the first hook that returns exactly `false`. A hook that raises is logged and skipped.

```lua
OPX.Hooks.Trigger(name, payload)
```

**Parameters**
- name: `string`
- payload: `table`

**Returns**
- `boolean` — allowed; `true` when no hook is registered

## Hook points [#hook-points]

Raised by the shipped modules (server side, all in `character`). Payload fields and refusal codes: [character](/docs/opx_infinity/character).

| Name | Payload | A `false` does |
|---|---|---|
| `money:beforeAdd` | `{ player, moneyType, amount, reason }` | refuses the credit |
| `money:beforeRemove` | `{ player, moneyType, amount, reason }` | refuses the debit |
| `money:beforeSet` | `{ player, moneyType, amount, reason }` | refuses the change |
| `paycheck:before` | `{ player, amount }` | skips that player's paycheck |
| `character:loading` | `{ citizenId, entity, data = {} }` | nothing: the result is not read. Hooks fill `data` (the `appearance` module puts `clothing` there). |

# CitizenId [#citizenid]

`lib/shared/citizenid.lua`, both sides. A citizen id is seven symbols from `34679ACDEFGHJKMNPRTWXYZ`, written `XXX-XXXX`. The seventh is a check symbol (weighted sum modulo 23), so one wrong symbol or two swapped neighbours are caught. `OPX.CitizenId.ALPHABET` holds the symbol set; changing it invalidates every id already issued.

## OPX.CitizenId.Build [#opx-citizenid-build]

Builds the id from six values (each taken modulo 23) and adds the check symbol.

```lua

```

**Parameters**
- values: `integer[]` — six

**Returns**
- `string`

## OPX.CitizenId.Generate [#opx-citizenid-generate]

A random id. Does not check the database for collisions.

```lua
OPX.CitizenId.Generate(rng)
```

**Parameters**
- rng?: `function(low, high)` — default `math.random`

**Returns**
- `string`

## OPX.CitizenId.Parse [#opx-citizenid-parse]

Case-insensitive; spaces, `-` and `_` are ignored.

```lua
OPX.CitizenId.Parse(input)
```

**Parameters**
- input: `any`

**Returns**

# JobGate [#jobgate]

`lib/shared/jobgate.lua`, both sides. Decides whether a character may use something gated by job. Used by `elevators`, `gunsmith`, `hauling`, `teleports` and `blips`; `shops` asks the character module instead.

## The JOBS format [#jobs-format]

```lua
JOBS = { ncpd = 2, medic = 0 },  -- job name -> minimum grade level
ON_DUTY = true,                  -- optional: must be on duty in that job
```

- One matching job is enough. A minimum of `0` means "anyone holding the job".
- No `JOBS`, or an empty one, means public: always open, even with no character data.
- A minimum that is not a number never matches (the gate stays shut), and `Problems` reports it.

The module turns this into a requirement `{ jobs = JOBS, onDuty = ON_DUTY }` and passes a snapshot of the character:

```lua
{ job  = { name = 'ncpd', grade = { level = 2 }, onDuty = true },
  jobs = { ncpd = 2, fixer = 0 },  -- every membership, grade only
  atMs = OPX.Now() }               -- when the snapshot was read
```

## OPX.JobGate.Evaluate [#opx-jobgate-evaluate]

A gated requirement fails on any doubt.

```lua
OPX.JobGate.Evaluate(requirement, snapshot, nowMs, policy)
```

**Parameters**
- requirement: `{ jobs, onDuty? }`
- snapshot: `table?`
- nowMs: `integer`
- policy?: `table`
  - maxAgeMs?: `integer` — default 0
  - membership?: `'primary' | 'any'` — default `'primary'`: only the worked job counts; `'any'` also counts other memberships for the grade (never for on-duty)

**Returns**
- allowed: `boolean`
- code?: `string` — nearest miss first: `off_duty`, `grade_too_low`, `job_required`; also `no_character` and `job_stale` (snapshot older than `maxAgeMs`, from the future, or a clock that cannot be read)

```lua title="Example"
local ok, code = OPX.JobGate.Evaluate({ jobs = row.JOBS, onDuty = row.ON_DUTY }, snapshot, OPX.Now())
if not ok then return OPX.Refuse(source, 'thing.' .. code) end
```

## OPX.JobGate.Problems [#opx-jobgate-problems]

Appends one line per malformed `JOBS` entry (not a table, or a name/grade that is not string → number). Job names are not checked against the character config.

```lua

```

**Parameters**
- jobs: `any`
- where: `string`
- lines?: `string[]`

**Returns**
- `string[]`

# Spots [#spots]

`lib/shared/spots.lua`, both sides. The shared format for places an operator writes down as coordinates and a player walks to. Used by `garages`, `dealership` and `clothing` (full record), and by `teleports`, `elevators`, `gunsmith` and `hauling` (coordinate box and marker look). `OPX.Spots.SHAPES` and `OPX.Spots.STYLES` hold the two allowed sets.

## The spot format [#spot-format]

```lua title="config"
SPOTS = {
  watson_kabuki = { KIND = 'garage', LABEL = 'Kabuki', X = -1442.2, Y = 127.4, Z = 18.0,
                    HEADING = 90.0, BUCKET = 0 },
}
```

| Field | Rule |
|---|---|
| key | String, 1 to `spec.maxKey` characters. |
| `KIND` | Required only when the module has kinds; one of `spec.kinds`, case-insensitive. |
| `LABEL` | Optional string; defaults to the key. |
| `X`, `Y`, `Z` | Finite numbers within ±1 000 000 (`OPX.Spots.BOUND`). |
| `HEADING` | Only for modules whose spec has `heading`; finite number, default `0.0`. |
| `BUCKET` | Whole number `>= 0`, default `0`. |

- A spot that breaks a rule is refused with a message and skipped.
- On the wire (server to client) the same record uses lower-case fields: `key, label, kind, x, y, z, heading, bucket`.
- A module's **spec** says how its spots differ: `{ noun, maxKey, kinds?, kindNames?, heading? }`. `noun` is the word used in refusals (`'spot'`, `'dealer'`, `'store'`).

## The marker format [#marker-format]

```lua title="config"
MARKER = { shape = 'ring', style = 'interaction', RADIUS = 1.5 },
MAX_DISTANCE = 60,     -- metres a marker is drawn from
GROUND_OFFSET = 0.06,  -- metres the marker sits above the floor
```

| Field | Allowed | Bad value |
|---|---|---|
| `shape` | `ring`, `cylinder` | the module's default shape |
| `style` | `interaction`, `objective`, `spawn`, `danger` | the module's default style |
| `RADIUS` | 0.1–50 | the module's default radius |
| `MAX_DISTANCE` | 1–500 m | the module's default |
| `GROUND_OFFSET` | 0–2 m | `0.06` |

Each field falls back on its own, so one typo does not reset the others.

# Spots on the client [#spots-client]

`lib/client/spots.lua`, client only. The markers and the key every spot module (garages, dealership, clothing, teleports, the elevator door) used to copy. Build on it instead of writing your own marker loop.

## OPX.Spots.Markers.New [#opx-spots-markers-new]

A set of engine markers kept in line with a spot list.

```lua
local set = OPX.Spots.Markers.New(options)
```

**Parameters**
- options: `table`
  - tag: `string` — your module id, for the one log line a refused marker writes
  - look: `function(spot): { shape, style, radius, lift }` — usually [`OPX.Spots.Marker`](#opx-spots-marker)
  - maxDistance: `function(): number` — metres; read once per pass
  - variant?: `function(spot): any` — a marker whose variant changed is remade

**Returns**
- set: `table`
  - `Reconcile(list, x, y)` — draws spots within range, removes the rest. Pass the position you already read (nil draws nothing). At most `OPX.Spots.MARKER_CREATES_PER_PASS` (8) creates per call; removals are never deferred.
  - `Clear()`, `Count()`, `Has(key)`, `Reset()`

```lua title="Example — a scheduler job"
local markers = OPX.Spots.Markers.New({
	tag = 'mymodule',
	look = function() return OPX.Spots.Marker(M.Config.MARKER, DEFAULT_LOOK) end,
	maxDistance = function() return OPX.Spots.MaxDistance(M.Config.MAX_DISTANCE, 60) end,
})
OPX.Scheduler.Every('mymodule.scan', 500, function()
	local x, y = OPX.Spots.PlayerXY()
	markers.Reconcile(M.Spots, x, y) -- 8 creates at most, so one pass stays cheap
end)
```

## OPX.Spots.Key.Register [#opx-spots-key-register]


# Storage [#storage]

`lib/server/storage.lua`, server only. The only door to the database (the MySQL bridge, which needs the `database.access` permission). Every call **yields** — call it from a thread, never at file scope — and answers a [Result](#result), never raising.

- Codes for the single-statement calls: `no-database` (bridge not installed), `query-failed` (`detail` holds the raw database error; log it, never show it to a player).
- Use named parameters (`@citizen`), and never put a SQL comment inside a statement.

## OPX.Storage.Query [#opx-storage-query]

```lua
OPX.Storage.Query(sql, params)
```

**Parameters**
- sql: `string`
- params?: `table`

**Returns**
- `Result` — value: list of rows

```lua title="Example"
local rows = OPX.Storage.Query('SELECT value FROM opx_thing WHERE citizen_id = @citizen', { citizen = citizenId })
```

## OPX.Storage.Single [#opx-storage-single]

**Returns**

**Returns**
- `Result` — value: one value

## OPX.Storage.Insert [#opx-storage-insert]

## OPX.Storage.Transaction [#opx-storage-transaction]

All or nothing.

```lua
OPX.Storage.Transaction(statements)
```

**Parameters**
- statements: `{ { query, values }, … }` — each a SQL string and its parameters, as the bridge's transaction takes them (shipped callers use `?` placeholders with `values`)

**Returns**
- `Result` — value `true`; errors `no-database`, `transaction-raised`, `transaction-failed` (rolled back)

```lua title="Example"
local done = OPX.Storage.Transaction({
	{ query = 'UPDATE a SET n = n - 1 WHERE id = ?', values = { 1 } },
	{ query = 'UPDATE b SET n = n + 1 WHERE id = ?', values = { 2 } },
})
```

## OPX.Storage.EnsureIndex [#opx-storage-ensureindex]

Adds an index to a table that may predate it; a no-op when it is present. Asks `information_schema.STATISTICS`, then runs `ALTER TABLE … ADD KEY`. Safe on every boot. Usually reached through [`OPX.Schema.AddIndexes`](/docs/opx_infinity/core/server#opx-schema-addindexes).

```lua

```

**Parameters**
- tableName: `string`
- indexName: `string`
- columns: `string[]` — at least one

Every identifier must match `^[%a_][%w_]*$`.

**Returns**
- `Result` — value `true` added, `false` already there; error `bad-index` (bad identifier or empty column list, `detail` = index name), or a storage code

```lua title="Example"
local ensured = OPX.Storage.EnsureIndex('opx_thing', 'idx_opx_thing_value', { 'value' })
```

# Audit [#audit]

`lib/server/audit.lua`, server only. One greppable line per entry in the server log: `[audit] event=… severity=… citizen=… user=… player=… message="…" data=…`. Text is stripped of control characters and cut. Never raises.

## OPX.Audit.Log [#opx-audit-log]

```lua
OPX.Audit.Log(entry)
```

**Parameters**
- entry: `table`
  - event: `string`
  - severity?: `'debug' | 'info' | 'warn' | 'error'` — default `info`
  - message?: `string` — cut to 200 characters
  - data?: `any` — cut to 200 characters
  - source?: `integer`
  - citizenId?: `string`
  - userId?: `string`

- The same event from the same owner within 10 s is collapsed; the next line says `[+N suppressed]`.
- `info`/`debug` events starting `money.` or `character.` are never collapsed.

```lua title="Example"
OPX.Audit.Log({ event = 'thing.reset', severity = 'warn', source = source, message = 'reset by staff' })
```
