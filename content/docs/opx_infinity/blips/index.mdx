---
title: blips
description: Map pins for garages, dealers, clothing shops, teleports and job sites, read from the modules that own those places.
---

Pins on the fullscreen map and the minimap. The module holds no coordinates of its own: every few seconds it reads the lists other modules already have on the client and turns them into pins, so a pin moves when the place moves. Categories are switched, re-sprited or ranged in `config/blips.lua`.

| | |
|---|---|
| Side | client only |
| Requires | none |
| Optional | `garages`, `dealership`, `teleports`, `shops`, `hud` |
| Contract | none |
| Config | `config/blips.lua` (shared) |
| Data | none |

The manifest must declare `ui.vanilla.map`; without `Open77.blips` the module says so once and draws nothing.

## Where the pins come from

| Category | Source | Pins |
|---|---|---|
| `garages` | [`garages`](/docs/opx_infinity/garages) client `Runtime.Spots()` (own bucket only) | **One per garage location, at its menu point** (the entry door is not pinned), labelled with the garage label. |
| `dealership` | [`dealership`](/docs/opx_infinity/dealership) client `Runtime.Spots()` (own bucket only) | One per dealer spot. |
| `shops` | `SHOPS` in the shops config | One per shop. |
| `teleports` | [`teleports`](/docs/opx_infinity/teleports) client entrance list | One per entrance (both ends of a two-way). Locked ones too. |
| `jobs` | gunsmith `ARMOURIES` and hauling `SITES` configs | Each armoury `BENCH`; each hauling site once (its `BLIP`, else its first real point) and each of its `DROPOFFS`. Not pinned when the player fails its `JOBS` gate. |

- Garage and dealer spots are the ones the server sent this client: `GARAGES` in `config/garages.lua` and `SPOTS` in `config/dealership.lua`, plus legacy database rows the server adopts at boot, filtered to the player's own bucket. The config files are not read directly.
- A point at exactly `0, 0, 0` is a placeholder: skipped and counted in the boot note.
- Pins are created in the order above until `MAX`; the rest are not pinned and a note says how many.
- The minimap shows pins only when the HUD leaves the vanilla `minimap` component visible (`VANILLA.minimap` in `config/hud.lua`); the fullscreen map always does. The boot note says which applies.

## Configuration

`config/blips.lua` sets `OPX.Config.MODULES.blips`. Shared script.

| Key | Default | Effect |
|---|---|---|
| <a id="config-blips-enabled" />`enabled` | `true` | `false` switches the module off. |
| <a id="config-blips-scan-ms" />`SCAN_MS` | `4000` | How often pins are reconciled with the sources. |
| <a id="config-blips-batch" />`BATCH` | `8` | Pins created or removed before the thread yields a frame. |
| <a id="config-blips-max" />`MAX` | `128` | Most pins this module creates; clamped to the platform quota of 128 per resource. |
| <a id="config-blips-categories" />`CATEGORIES` | see below | One block per category. |

```lua title="config/blips.lua — one category"
garages = { SHOW = true, SPRITE = 'vehicle', LABEL = 'Garage', RANGE = 0, WALLS = false },
```

- `SHOW`: `false` hides the category.
- `SPRITE`: vanilla sprite — an alias (`vehicle`, `objective`, `clothes`, `fast_travel`, `guns`, `quest`, …), a 2.31 variant name or an integer 0–146. **The sprite is the colour**: there is no colour option. HUD-only sprites (`ping_*`, `remote_player`) may not appear on the fullscreen map.
- `LABEL`: description line on the pin (the title is the place's own label). Default: the category name.
- `RANGE`: metres, 0–4000; `0` = always visible. Out of range hides the pin on HUD, minimap and map alike.
- `WALLS`: `true` shows the pin through walls.

| Category | `SPRITE` | `LABEL` | `RANGE` |
|---|---|---|---|
| `garages` | `vehicle` | `Garage` | `0` |
| `dealership` | `objective` | `Vehicle Dealer` | `0` |
| `shops` | `clothes` | `Clothing Shop` | `400` |
| `teleports` | `fast_travel` | `Shortcut` | `0` |
| `jobs` | `guns` | `Job Site` | `0` |

All default to `SHOW = true`, `WALLS = false`. A category name outside these five is reported at boot. `COLOR`, `COLOUR`, `ALPHA`, `OPACITY`, `SCALE`, `CATEGORY`, `SHORTRANGE` or `SHORT_RANGE` in a category is reported at boot with the setting to use instead, because the engine refuses those options.
