Glowing markers where players fetch and park their own vehicles. On foot at a **menu point** or at the **entry point**, the key (**E** by default) opens the list of every vehicle filed under that garage. Sitting in one of your own vehicles at the entry point, the same key puts it away. A vehicle comes out at the first free **exit** of the location you stand at. Garages are written in `config/garages.lua`; nothing is placed in game.

| | |
|---|---|
| Side | both |
| Requires | `character` (hard) |
| Optional | `vehicles`, `prompts`, `downed`, `menu`, `vehiclekeys` |
| Contract | `garages` v1 — [server](/docs/opx_infinity/garages/server), [client](/docs/opx_infinity/garages/client) |
| Config | `config/garages.lua` (shared) |
| Data | `opx77_garages` (legacy, read-only) |

- Without `vehicles` every request is refused.
- Without `menu` the list cannot open; `/opx.garages.bring` still works.
- Without `prompts` the markers still draw, only the key row is missing.
- With [`vehiclekeys`](/docs/opx_infinity/vehiclekeys), the owner is given a key on the way out when their bag holds none to that plate; a full bag is said to the player and does not stop the car coming out.

## How a garage works

- A **garage** is a key (e.g. `garage1`). A vehicle's `garage` column holds that key, so a car stored at one location comes out at every location of the same garage.
- Each **location** has one `MENU` point (opens the list), one `ENTRY` point (takes the car you sit in) and an ordered list of `EXITS`.
- **Exits** are tried in the order written. An exit is taken when any vehicle in the same routing bucket is within `EXIT_CLEARANCE` metres (the car being fetched never blocks its own exit), or when it is **promised** to another bring-out still spawning: two players fetching at once get two exits, never one car inside the other. A promise lapses after 10 s. All taken: `garages.noFreeExit`.
- **Put away or bring out** is decided by the server from the host's seat assignment, never by the client. Sitting in someone else's car at the entry point is refused with `garages.notYours` ("Only your own vehicles go in here."), instead of bringing one of yours out beside you. On foot, the entry point opens the list and its prompt reads *Open your garage*; a player with two cars filed there picks one.
- The list shows each car as `Villefort Cortes · 8XK2L0P`: the same name as its key ([`OPX.Vehicle.DisplayName`](/docs/opx_infinity/core/lib#opx-vehicle-displayname)), the plate as the value.
- A refused bring-out is **one** toast that names the garage (no more three toasts and a platform notice).
- Toasts name the car as the list does: *Brought out Archer Hella · AA111AA.*, *Put away …*, *Recalled … here.* for a car already out that was moved. The staff bring command uses the same words.
- A player who is down is refused (`error.incapacitated`). A refusal names back the garage key only when it is a known spot or garage.
- E is shared with doors, dealers, fitting rooms, lifts and teleports: the nearer spot acts, and only its prompt row is drawn; while the list is open, E closes it (rank `OPEN`). See [One press, one owner](/docs/opx_infinity/core/lib#key-contest).
- A car with **passengers** is not put away: `garages.passengers` until they get out.
- The nearest point is searched in the player's own bucket only, so an instanced copy on the same spot does not get in the way.
- A car of yours already out elsewhere is **moved** to the exit (see [`vehicles.Spawn`](/docs/opx_infinity/vehicles/server#server-vehicles-spawn)); refused with `vehicle.occupied` if anyone sits in it.
- `KIND = 'garage'` brings out ground vehicles only; `KIND = 'avpad'` AVs only. An AV is created `AV_LIFT` metres above the exit. Which records are AVs is `AV_PREFIXES` in `config/shared.lua`.

### Legacy table `opx77_garages`

- `/opx.garages.add` and `/opx.garages.remove` are gone.
- At every boot the server reads `opx77_garages` and adopts each row whose key is **not** in `GARAGES` as a garage of one location whose menu, entry and only exit are the captured point.
- Each adopted garage is printed to the server log as `[garages] config line: ...`, ready to paste into `config/garages.lua`, then a warning says how many exist only in the table.
- A config garage with the same key wins. Nothing writes to or drops the table.

## Commands

| Command | Access | Arguments | Effect |
|---|---|---|---|
| <a id="opx-garages-list" />`/opx.garages.list` | ACL `command.opx.garages.list` | — | Every garage: kind, label, each location's points, exit count, bucket, config or legacy table. |
| <a id="opx-garages-bring" />`/opx.garages.bring` | ACL `command.opx.garages.bring` | `[garage] [plate]` | Brings one of the caller's own vehicles out at the garage they stand at. `garage`: a garage key (nearest point of it) or omitted (nearest point). `plate`: one of yours; omitted = first eligible. ## Configuration

`config/garages.lua` sets `OPX.Config.MODULES.garages`. Shared script.

| Key | Default | Effect |
|---|---|---|
| <a id="config-garages-enabled" />`enabled` | `true` | `false` switches the module off. |
| <a id="config-garages-use-radius" />`USE_RADIUS` | `4.0` | Flat metres from a point's X/Y within which it can be used. The server allows [`REACH_SLACK`](/docs/opx_infinity/core/config#config-shared-reach-slack) (1 m) more. |
| <a id="config-garages-exit-clearance" />`EXIT_CLEARANCE` | `3.0` | Flat metres around an exit that must be free of vehicles. |
| <a id="config-garages-marker" />`MARKER` | `garage = cylinder/spawn/2.5`, `avpad = ring/objective/3.5`, `entry = ring/interaction/3.0` | Marker look per kind (menu points) and for entry points. Each `{ shape, style, RADIUS }`. |
| <a id="config-garages-max-distance" />`MAX_DISTANCE` | `150.0` | Metres beyond which a marker is not drawn (1–500). |
| <a id="config-garages-ground-offset" />`GROUND_OFFSET` | `0.06` | Metres the marker is lifted off Z (0–2). A ring at exact floor height is invisible. |
| <a id="config-garages-av-lift" />`AV_LIFT` | `1.2` | Metres above the exit an AV is created (0–10). |
| <a id="config-garages-scan-ms" />`SCAN_MS` | `500` | Client marker scan interval. |
| <a id="config-garages-poll-ms" />`POLL_MS` | `15000` | How often the client re-asks for its points. |
| <a id="config-garages-request-window-ms" />`REQUEST_WINDOW_MS` | `10000` | Length of the per-player request window. |
| <a id="config-garages-requests-per-window" />`REQUESTS_PER_WINDOW` | `6` | Requests per window (bring-outs and lists together). |
| <a id="config-garages-cooldown-ms" />`COOLDOWN_MS` | `3000` | Minimum gap between two bring-outs from one player. |
| <a id="config-garages-key" />`KEY` | `{ ID = 'opx.garages.use', NAME = 'garages.key.use', DEFAULT = 'E' }` | The key mapping. `ID` is stable (rebinds are stored under it). `DEFAULT = false` registers no key. |
| <a id="config-garages-menu" />`MENU` | `{ ANCHOR = 'center', WIDTH = 560, HEIGHT = 560, MAX_HEIGHT_VH = 88, VISIBLE_ROWS = 12 }` | Size of the list panel. The menu module clamps every value. |
| <a id="config-garages-commands" />`COMMANDS` | `{ list = 'opx.garages.list', bring = 'opx.garages.bring' }` | Command names. An empty name registers nothing. |
| <a id="config-garages-garages" />`GARAGES` | `garage1`, `garage2` (one location each) | Every garage. See below. |

Markers use the engine vocabulary: shape `ring` or `cylinder`; style `interaction`, `objective`, `spawn` or `danger`; `RADIUS` 0.1–50. A bad field falls back to the module default and is reported at boot.

```lua title="config/garages.lua — one GARAGES entry"
GARAGES = {
    garage1 = {                        -- the key: 1-48 chars, never rename it
        LABEL = 'Watson Garage',       -- shown to players, not translated; defaults to the key
        KIND = 'garage',               -- 'garage' (ground vehicles) or 'avpad' (AVs)
        LOCATIONS = {
            {
                BUCKET = 0,            -- routing bucket of the whole location
                MENU  = { X = -1527.21, Y = -218.56, Z = 7.86 },
                ENTRY = { X = -1527.21, Y = -218.56, Z = 7.86, HEADING = 199.6 },
                EXITS = {
                    { X = -1527.21, Y = -218.56, Z = 7.86, HEADING = 199.6 },
                },
            },
        },
    },
}
```

- Every point follows the shared spot rules ([spot helpers](/docs/opx_infinity/core/lib)): `X`, `Y`, `Z` finite and within ±1,000,000; `HEADING` finite (default `0`); `BUCKET` a whole number ≥ 0 (default `0`). Only X and Y are measured against.
- A garage with any bad point, no location, or a location without exits is refused whole, with a boot warning naming it.
- To capture a point, stand on it facing the way a car should come out and run `/opx.admin.self.pos`; it copies position and heading to your clipboard.

<Callout type="warn">

Never rename a garage key. Every vehicle filed under the old key is orphaned.

</Callout>

## Refusal codes [#codes]

Each code is also a locale key. Codes from [`vehicles`](/docs/opx_infinity/vehicles#codes) (`vehicle.occupied`, `vehicle.busy`, `vehicle.spawnRefused`, …) pass through unchanged.

| Code | Meaning |
|---|---|
| `garages.noVehicles` | No `vehicles` contract on this server. |
| `garages.noCharacter` | No character loaded. |
| `garages.noPosition` | The player's position could not be read. |
| `garages.noSuchSpot` | No point underfoot, or the named key does not exist. |
| `garages.wrongBucket` | The point is in another routing bucket. |
| `garages.tooFar` | Further than `USE_RADIUS` from the point. |
| `garages.nothingHere` | The player owns nothing of this garage's kind. |
| `vehicle.notFound` | The named plate is not one of the player's eligible vehicles. |
| `garages.noFreeExit` | Every exit of the location is taken. |
| `garages.notYours` | Seated in a car that is not yours at the entry point. |
| `garages.passengers` | Passengers are still in the car you want to put away. |
| `error.incapacitated` | The player is down. |
| `garages.rateLimited` | Cooldown or request window (bring-outs). |
| `error.tooFast` | Request window (lists). |
| `error.noPermission` | Client side only: another surface holds the keyboard. |
