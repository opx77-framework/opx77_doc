title: admin
description: The staff tool — a menu, rows on the target eye and 56 restricted commands to move, heal, arm, equip, moderate and audit players.
---

Staff press **F9** (or type `/opx.admin`) to open a menu that finds a player, goes to them, heals or moves them, gives them a car, a weapon or an item, kicks or bans them, and reads the audit. The same actions are rows on the target eye and chat commands. Every action is a restricted command, so the server's ACL decides who may run what. Nothing is stored in the database.

## Granting access [#granting]

The module checks no permission itself: the host resolves `command.<name>` against `acl.jsonc` before any handler runs. The menu and the eye only grey out or hide what the ACL would refuse.

- `command.opx.admin` opens the menu. Holding it is what makes someone "staff" for [`IsStaff`](/docs/opx_infinity/admin/server#server-admin-isstaff) and for the badge on name tags.
- `command.opx.admin.*` covers every action. Only a rule ending in `.*` is a prefix, so it does **not** cover the opener: an operator role needs **both**.
- Narrower families work too, e.g. `command.opx.admin.player.*`. The `character.*` commands are separate on purpose: `list` shows one account's characters, `find` searches everyone who ever played, `rename`/`delete` change rows that outlive a session.
- The menu and eye also run other modules' commands, named in [`LINKS`](#config-admin-links): `opx.players`, `opx.where`, `opx.job`, `opx.gang`, `opx.money`, `opx.save`, `opx.inventory.open`, `opx.inventory.holders`, `opx.weather.set`, `opx.weather.next`, `opx.weather.freeze`, `opx.time`, `opx.time.freeze`. Grant those too (e.g. `command.opx.weather.*`, `command.opx.time`, `command.opx.time.*`).
- **The eye hides what the menu greys.** The menu draws a refused row and marks it; the eye does not register it at all, so a missing grant looks like a missing feature. The client writes the dropped grants to the server journal, e.g. `[admin] target rows, player 3: … this ACL does not grant: opx.inventory.open opx.weather.set` — each name is a `command.<name>` to add.
- A short alias is gated on the long command's right, never on its own name.

## Commands

56 restricted commands (the opener + 55 actions). The right is always `command.` + the full name.

- *target* `playerId|me`: a server id, or `me`/`self` for the caller. *holder* `playerId|me|citizenId`: also a citizen id, online or offline.
- Switches take `on`/`off` (also `true`/`false`, `1`/`0`, `yes`/`no`); left out, they toggle.
- "In game": the console gets `in_game_only`.
- Moving, reviving, healing, killing and spawning for a player need that player's readiness gate open (`not_incarnated`, `gate_closed`, `gate_unreadable`). A move is a kill + respawn at the new point, health set to `PLACEMENT.HEALTH`, with a grace window; if the respawn is refused, the player is revived where they stood.
- Per-operator cooldown per command: 400 ms for actions, 1000 ms for reads (`RATE` + tunables); `too_fast` inside it. The console has none.
- Every action writes an audit line; the target gets a toast unless they are the caller.

## Refusal codes [#codes]

Locale key `admin.error.<camelCase>` (e.g. `bad_target` → `admin.error.badTarget`). Typed-input codes show as warnings, the rest as errors.

| Code | Meaning |
|---|---|
| `in_game_only` | Needs a player, not the console. |
| `too_fast` | Inside the operator's cooldown. |
| `failed` | The handler raised; the log names it. |
| `no_target`, `bad_target`, `not_connected`, `self_target`, `console_has_no_player` | Target missing, malformed, offline, the caller where not allowed, or `me` from the console. |
| `not_incarnated`, `gate_closed`, `gate_unreadable` | The player's body cannot be acted on yet. |
| `no_position` | The host has no position for the player. |
| `kill_refused`, `respawn_refused`, `refused` | The host refused; its reason is shown. |
| `bad_coordinates`, `bad_switch`, `bad_duration`, `empty_text` | Malformed argument. |
| `unknown_vehicle`, `vehicle_cap`, `no_vehicle`, `occupied`, `unsafe_repair`, `bad_scope`, `unknown_flag`, `not_ours`, `vehicles_unavailable`, `keys_unavailable` | Vehicle commands. |
| `unknown_weapon`, `unknown_ammo`, `not_armed`, `holster_unavailable`, `give_partial` | Weapon commands. `not_armed`: holster target has no weapon drawn. `holster_unavailable`: no `HolsterWeapon` on the inventory contract, or it failed. `give_partial`: weapon given, ammo refused, weapon could not be taken back. |
| `inventory_unavailable`, `bad_holder`, `no_character`, `unknown_citizen`, `unknown_item`, `bad_count`, `not_enough`, `bag_no_room`, `bag_too_heavy`, `bad_amount`, `bad_type`, `vetoed` | Inventory or character contract refusals. |
| `unknown_location`, `bad_location_name`, `seeded_location` | Locations. |
| `bad_door`, `door_limit`, `doors_networked`, `doors_unavailable` | Doors. |
| `combat_unavailable` | No `Open77.combat.setFriendlyFire` on the host. |
| `unknown_ped`, `models_unavailable` | Ped models. `models_unavailable`: no `players.setModel` native. As of 2.31.13+op77.78 it is in **no** published server build, so `self.model` and `player.model` always answer this today (one server log line). |
| `appearance_unavailable` | `player.wardrobe` without the `appearance` contract. |
| `bad_name`, `characters_unavailable`, `search_short`, `bad_request` | Character commands. |
